Proceso de certificación para ser emisor electrónico

Tener una biblioteca que genere XML no autoriza por sí solo a emitir e-CF en producción. La DGII documenta un proceso de solicitud y certificación del contribuyente.

En esta guíaLas etapasPreparación técnicaPapel del paqueteFuentes DGII

Las etapas

  • Solicitud para ser emisor electrónico mediante el formulario indicado por la DGII.
  • Pruebas de adecuación e integración en pre-certificación y postulación en el portal de certificación.
  • Set de pruebas para demostrar que el sistema puede operar con los servicios y formatos exigidos.
  • Autorización como emisor electrónico al completar satisfactoriamente el proceso.

El documento de certificación distingue el sistema desarrollado internamente de uno adquirido a un proveedor y solicita datos del software durante la postulación. También indica que puede utilizarse el ambiente de pre-certificación para probar la integración antes de iniciar el set formal.

Preparación técnica

En las pruebas de datos, el contribuyente descarga un set de datos en Excel, genera XML de e-CF con los campos y el orden indicados, y los remite para validación. El proceso también incluye un set de aprobaciones o rechazos comerciales. La postulación se genera como XML, se firma y se carga al portal antes de habilitar las pruebas. Conserva TrackId, estados y mensajes para depurar los casos rechazados.

Clave técnica

El procedimiento y los requisitos se rigen por la versión vigente publicada por la DGII. Este artículo resume el flujo del documento de certificación incluido en el archivo oficial del 22 de octubre de 2026.

Papel del paquete

SellerNet ayuda con las operaciones técnicas de .NET. El contribuyente realiza su propia solicitud y obtiene la autorización de la DGII; el paquete no sustituye esa etapa.
